# Customer Account profile reliability — October 24, 2026

The Account page formerly loaded once on mount, retained a previous profile after an Auth change, and reported success when an update returned no error even if it matched no row. It now uses the existing verified-account hook and mounts its editor only for a confirmed, non-anonymous current owner. Owner changes unmount the old editor; stale/aborted reads and writes cannot restore old details.

The profile read and name save independently reverify the owner with Auth getUser. Auth supplies the current email and account-created date; missing/invalid dates display Not recorded. Database responses are allowlisted to id,full_name,updated_at and validated before display. Missing profiles, failed reads, changed identities and unconfirmed email have distinct fixed messages. Raw database/Auth errors are never displayed.

Save trims the name (empty becomes null; at most 200 characters) and sends only full_name. It matches both the verified owner UUID and the previously read protected updated_at value. The existing database trigger maintains this timestamp and browsers cannot update it directly; no migration or grant change is needed. A concurrent edit makes the stale update match zero rows instead of overwriting newer details. Success requires the returned owner, normalized name and valid server timestamp. A zero-row result requires reload. A lost/malformed/error response is uncertain because the write might have committed: automatic retry is disabled and another save is blocked until a fresh read succeeds. This does not make an in-flight HTTP write reversible; the revision filter prevents a late old write from overwriting a newer revision.

The editor coalesces duplicate submissions, disables edit/cancel/reload controls while saving and bounds read/save waits to 20 seconds. A timed-out read shows recovery; a timed-out save stays uncertain. Cleanup aborts requests and removes timers. Cancel restores the loaded name. Phone controls have 48px save/cancel/reload targets and a 44px edit target, with wrapping email/name and no horizontal overflow at 320px.
