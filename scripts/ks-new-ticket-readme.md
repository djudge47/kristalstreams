# Verified customer ticket creation — October 24, 2026

The previous general New Support Ticket form retained drafts across sign-in changes. It submitted for whichever user getUser returned at Save time, rather than the owner who started the form; only setup-help had a partial identity guard. Its insert did not return a row, controls stayed editable while saving, and it had no bounded save/uncertainty state. A setup-order check waiting on getSession could stay loading after its abort timer.

The route now mounts a form keyed to the verified confirmed, non-anonymous account and general/setup-help mode. Account rechecks unmount the old form and clear its draft. Signed-out/unconfirmed/error states do not mount private inputs or request private records. The shared create helper rechecks the exact captured owner before dispatch, trims/bounds fields and accepts only listed category/priority values. It inserts only user_id,subject,description,category,priority,status:open. The projection is the existing explicit ticket allowlist; success requires the exact returned owner, subject, description, category, priority, status and valid server ID/date before replacing the form route with the ticket list.

Subject input is limited to 200 characters and description input to 10,000. The submitted description has a 12,000-character maximum including the existing validated order attachment. A fieldset freezes editable inputs while saving; Cancel and setup-order changes are disabled too. The synchronous guard coalesces repeated submissions. Save waits at most twenty seconds; cleanup aborts/discards late work and prevents stale completion from navigating or updating state.

Lost, empty, malformed or error insert results are uncertain because a ticket may already exist. Automatic insert retry is disabled and the current form remains blocked, with a clear link to check support tickets before starting another one. This is a UI guard, not durable idempotency across remounts/reloads/tabs; the existing schema does not permit client-supplied ticket IDs and no privileges are widened. An aborted request does not guarantee reversal of a dispatched insert. No email delivery is promised.

Setup-help still offers the same reviewed order selection and allowlisted snapshot attachment. Its session must match the verified form owner before fetching orders; wrong-owner sessions cannot attach data. A stalled check reaches the visible unavailable state at twenty seconds and discards delayed results. A failed optional order check permits a general ticket without fabricated order details. Existing order validation and saved status/payment-versus-provisioning distinctions are retained.
