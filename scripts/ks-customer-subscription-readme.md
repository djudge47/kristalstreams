# Subscription ownership and missing-profile recovery — October 24, 2026

The previous Subscription page read its website profile once from a stored session, retained it after account changes and had no stale-response/unmount guard. It mounted the private streaming-service component only after a profile row existed, so a missing or failed website profile could prevent valid linked service/payment records from being checked. Unknown profile values could become one connection or a No Active Website Plan claim; profile updated_at was labeled Started / Updated. The fallback included an unresponsive wide comparison table and a countdown calculated only on render.

Only the current verified confirmed, non-anonymous owner now mounts the keyed workspace. The linked service/payment component mounts independently of the website-profile read. Its own owner-bound implementation and backend remain unchanged. Website fallback is allowed only after the same current account reports unlinked or hidden; linked, pending, failed, signed-out and foreign callbacks cannot expose stale website dates. Refresh subscription clears the previous status, rechecks the profile and remounts the service component with a new generation, ignoring callbacks from the previous check. This also recovers an earlier hidden/unavailable rollout without needing a full page reload.

The profile helper rechecks current Auth before a SELECT of exactly id,subscription_tier,subscription_status,connections_allowed,subscription_expires_at,updated_at with an owner UUID filter. It validates identity, nullable bounded text, nullable nonnegative integer connections and nullable timestamps. Missing, failed, foreign and malformed rows remain distinct from no active service or missing payment. Unknown values display Not recorded, never a fabricated connection count. No row is inserted or modified.

Website data remains explicitly separate from streaming activation, payment and service expiration. The fallback uses wrapping phone-friendly fields and a link to the maintained current pricing page instead of a duplicate static comparison table. Profile updated_at is Website record updated, not a plan start/payment timestamp. The stale countdown is removed; the saved expiry remains visible and clearly scoped to website access. No active/inactive provider state is inferred from website-plan fields, and existing linked service expiration/payment precedence is preserved.

The existing checkout-return helper remains called for success=true inside the captured owner's profile loader; the resulting read still rechecks that exact confirmed owner before dispatch. The shared Auth checker uses the installed SDK's verified getUser flow and normal session initialization/refresh behavior. No session, recovery, checkout or Auth configuration is changed. Profile reads inherit the existing twenty-second deadline/abort/generation handling and ignore late or unmounted results. Recovery buttons and support remain available without asking a customer who already paid to pay again.
