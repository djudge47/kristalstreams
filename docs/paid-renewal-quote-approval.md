# Exact paid-renewal quote approval

This backend step records one exact approved quote per existing paid-renewal review operation. A new payment, replacement operation or live provider write is never created by approval. It does not borrow the historical manual renewal's consent or limits.

The authenticated administrator first obtains the existing `paid-renewal-verification` view. A compatible result now includes a public quote fingerprint, requested package label and credit cost. Private quote facts bind the paid review fingerprint, owner-selected service, current line/package/expiry, requested terms, selected channels, catalog fingerprint and exact cost. Observation time and available balance are checked independently; they do not make an otherwise identical refreshed quote a different approval.

The same POST view accepts `action:save-quote-approval` with the reference, existing operation ID, expected quote fingerprint, exact credit cost and three explicit confirmations: approval only, channel preservation and service changes reviewed. It independently rereads XUI through the existing GET-only adapter, rechecks current ownership/service before and after, and rejects changed terms, channels, catalog or cost. The database independently checks current confirmed administrator identity, the private current binding, quote structure/hash, credit bounds and a 30-second evidence window before insertion.

The immutable private table has one approval per operation. Its advisory lock serializes competing saves. Matching retries return the saved approval; conflicting saves cannot replace it. A lost save acknowledgement recovers the same approval without another provider read. Replaying an expired approval preserves its ID and original deadline and returns `review_required`; it cannot extend validity. Recovery reports saved facts and current local ownership/expiry only, never a fresh provider or activation claim.

Every response retains `mayDispatch:false` and `providerActivated:false`. No release switch, customer/profile/receipt, email, provider operation, credit reservation, execution slot or dispatch claim is changed. There is no new Vercel function. The existing manual consent, budget and execution protocols remain unchanged. No new administrative UI or Production release is included.

This is approval of review evidence, not permission to spend credits. A future execution flow still needs explicit execution/credit consent, fresh evidence, a reviewed provider timing policy, durable current-fact claims, physical reseller/line exclusions, completion/reconciliation and credential delivery before coordinated release.

Tests use actual disposable SQL/RPC and intercepted Auth/provider transport. They cover exact-cost saves, lost acknowledgements, cost/channel drift, unavailable XUI reads, current administrator confirmation, HTTP overrides, private roles and immutable records. Native PostgreSQL tests independently race identical/conflicting saves, roll back a first writer, reject stale evidence and recover expired approvals without replacing or extending them.
